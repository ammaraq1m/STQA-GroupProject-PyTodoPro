# PyTodo Pro · QA throughout Agile and DevOps

| Lifecycle stage | Evidence motivating change | Proposed team activity and exit evidence |
| --- | --- | --- |
| Backlog refinement | Week 1/2 eight-character password and due-today failures (DEF-001/002). Week 7 has 32 inferred requirements. | Product, QA and development review acceptance criteria before work starts. Write inclusive bounds, time-zone rules, expected messages, API responses and data invariants in the story and RTM. Assign a requirement owner. |
| Design and shift-left testing | Exact seven-day and zero-age errors (DEF-003/004) propagated to both dashboards. Week 4 validation diverged between routes (DEF-010, DEF-021–024). | Design boundary and state-transition tables first. Add deterministic helper oracles, typed API contracts and cross-interface tests. Verify invalid input leaves state unchanged. |
| Implementation and peer review | Invalid dates were persisted before error (DEF-009). API query binding, deletion owner scope and signing configuration were flagged (DEF-006/007/026). | Require a reviewer to check validation order, transaction boundaries, permission policy per method, query binding and secret configuration. Use static checks with human disposition. Attach review evidence to the change. |
| Build and continuous testing | Initial Week 6 staging blocked 16 records. The final run still had 20 assertion failures. | Pin tools, use disposable fixtures, run the smoke lane on changes and full regression on the schedule/candidate. Preserve JUnit, JSON and screenshots by build and distinguish setup failure from product failure. |
| Sprint review and user validation | Week 3 first-use, labels, reflow and layout issues (DEF-011–020). Native devices, screen readers and participant results are pending. | Make keyboard and accessible names reviewable with each UI story. Combine axe checks with manual native zoom/device and participant tasks before accepting core journeys. |
| Release readiness | Week 5 deployment/TLS scope is unverified and paced reads cannot establish capacity. Week 8 exit gates E1–E4 are unmet. | Review STRIDE changes and defensive controls, verify staging configuration and agree on load/error/latency limits. Require closure evidence, completed manual coverage or an approved exception and named sign-off. |
| Operate and learn | Missing mutation audit (DEF-027), malformed-date effects across requests and no tested restart. | Define durable audit events and service health measures. Give owners a runbook for recoverability checks and incident review. Route defects to the backlog with affected data, version and verification evidence. |
| Retrospective and defect prevention | Week 6 reproduced all 39 reused verdicts, including 17 failures. Week 8 preserved 29 open canonical findings. | Review root causes and recurrence by module. Choose a corrective action such as common validation or a boundary test; measure its effect using comparable runs. Review open defects and fix verification before closing the action. |

Use the Week 8 test case, consolidated defect and RTM IDs throughout requirements reviews, changes, triage and acceptance. Carry availability of manual testers, platform access and deployment criteria as explicit dependencies. Suggested ownership is product/acceptance lead for requirements; engineering and QA for implementation and verification; operations for environment and release evidence.
